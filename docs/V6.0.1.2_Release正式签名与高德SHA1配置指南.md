# FamilyGuard V6.0.1.2 — Release 正式签名与高德 SHA1 配置指南

## 目标

本工程使用独立的 Release keystore 对正式 APK 签名。Debug 和 Release 证书不同，高德 Android Key 必须同时登记正确的 Debug SHA1、Release SHA1，以及 applicationId `com.familyguard.app`。

## 你需要亲自完成的操作

1. 在自己的 Windows 开发机上解压工程，使用 Android Studio 打开 `android/`。
2. 确认 Gradle JDK 为 17，Android SDK Platform 35 与 Build Tools 已安装。
3. 在 PowerShell 中运行：

   ```powershell
   cd <解压目录>\FamilyGuard_V6_Complete\android
   powershell -NoProfile -ExecutionPolicy Bypass -File .\GENERATE_RELEASE_SHA1_WINDOWS.ps1
   ```

4. 脚本提示时输入一个至少 16 位的强密码并再次确认。密码不会显示在屏幕。脚本在本机创建：
   - `%USERPROFILE%\.familyguard\keys\familyguard-release.jks`：Release 私钥库（放在项目目录之外，避免误提交）；
   - `android/keystore.properties`：Gradle 本地签名配置（含明文密码，只留本机）。
5. 脚本输出 `Release SHA1`。复制这个 SHA1 到高德控制台的「发布版安全码 SHA1」。不要把它填到「调试版安全码 SHA1」。
6. 高德控制台填写：
   - 服务平台：Android 平台 SDK；
   - 发布版安全码 SHA1：本脚本输出的 Release SHA1；
   - 调试版安全码 SHA1：当前 debug.keystore 的 SHA1（用户此前提供值为 `B6:3B:7C:2E:67:BE:D6:59:D4:72:CC:5E:1D:C4:7F:20:43:5A:0B:63`，前提是它确实来自本机 `%USERPROFILE%\.android\debug.keystore`）；
   - PackageName：`com.familyguard.app`。
7. 保存高德 Key 配置后，执行：

   ```powershell
   .\gradlew.bat :app:verifyAmapConfiguration :app:verifyReleaseSigning
   .\BUILD_RELEASE_WINDOWS.cmd
   ```

8. Release APK 输出：

   `android\app\build\outputs\apk\release\app-release.apk`

9. `VERIFY_RELEASE_APK_WINDOWS.ps1` 会使用 Android SDK 的 `apksigner` 验证 APK 签名。还应在 Redmi K90 和家长端设备上安装测试，并确认高德地图加载、定位回调、服务器 HTTPS、登录配对、围栏、断网补传等功能。

## 密钥安全（强制）

- `familyguard-release.jks` 和 `keystore.properties` 都不得提交 Git、发聊天、上传公开网盘或放进交付 ZIP。
- 至少保留两份离线备份，建议加密 USB + 独立安全位置；密码放密码管理器，不能只存在电脑上。
- 不要重新生成第二个 keystore 来签后续版本。用户已安装的 Release APK，后续更新必须由同一签名密钥签名，否则 Android 会拒绝覆盖安装。
- 不要把 JKS、密码或私钥发给协助者。需要协助时只提供 SHA1、Gradle 日志和脱敏配置。
- 本工程 `.gitignore` 已忽略 `keystore.properties`、`keystore/`、`*.jks`。

## 如果以后发布到 Google Play

Google Play App Signing 下通常存在「上传密钥」与「应用签名密钥」两种证书。上传密钥用于上传 AAB；用户从 Play 安装的 APK 由 Play 的应用签名密钥签名。高德 Key 的 Release SHA1 应以实际安装包使用的证书为准，Play 分发场景应在 Play Console 的 App integrity 页面读取 App signing key certificate SHA1，而不能误填 upload key SHA1。若只在家庭设备间直接分发 APK，则使用本地 Release keystore 的 SHA1。

## 当前工程自动化保护

- `:app:verifyReleaseSigning`：Release 签名文件、属性和别名缺失时失败关闭；
- `assembleRelease` / `bundleRelease`：依赖签名检查，避免生成未签名的生产包；
- `BUILD_RELEASE_WINDOWS.cmd`：先验证高德 Key 与 Release 签名，再构建并校验 APK；
- `VERIFY_RELEASE_APK_WINDOWS.ps1`：调用 `apksigner verify --print-certs` 检查最终 APK 签名。

## 生产发布仍需的人工验收

签名成功只证明 APK 由指定证书签名，不代表产品已达到生产级。还需完成真机定位与后台权限测试、Android 版本兼容测试、高德 Key 实际鉴权、HTTPS 证书与服务器安全、隐私政策和数据保留/删除流程、崩溃与弱网测试、备份恢复演练。
