# V4.2 核心定位优化与测试说明

## 对 V4.1 的改动

1. Android `TrackingService` 增加系统融合定位 `LocationManager.FUSED_PROVIDER`（Android 12+/API31 起存在并已启用时），原生卫星 GNSS 和网络定位仍各自独立运行。Android 12+ 的请求显式设置 `QUALITY_HIGH_ACCURACY`、禁用批处理、允许 0 米位移更新。
2. `AccuracyPolicy` 增加来源切换滞回，并对不可信的瞬间高速跳点进行合理性校验。跳点判断使用实际位置时间差与误差半径；无法比较 WGS84/GCJ-02 时不以不同坐标系的原始数值计算距离。无 Key 模式中都是 WGS84。
3. 位置缓存改为 `AtomicReference` 只保留最新待保存快照，避免 HTTP 超时期间持续排队大量 SQLite 写入任务；SQLite 仍原子覆盖并加密最新点。
4. 系统定位开关变化后重新检查 provider 可用性，尝试重新订阅；增加启动时近期定位缓存读取。通知更新节流到约 3 秒，**定位采集本身不降频**。
5. Go `/v1/position` 支持 `provider=fused`；家长界面显示实际来源，不将估算误差视为实际测距精度；未配置高德 Key 也能共享/查看最新经纬度。
6. 修订 Debug Manifest 的明文局域网连接覆盖声明；Release 仍要求 HTTPS。

## 能执行的测试与限制

- `go test -count=3 ./...`：通过；`go test -race -count=1 ./...`：通过；`go vet ./...`：通过。
- `javac -encoding UTF-8 -d <目录> android/app/src/main/java/com/familyguard/app/AccuracyPolicy.java android/tests/AccuracyPolicySelfTest.java` 后执行 Java 主类：31 项检查通过。
- Linux 和 Windows x64 服务端均完成交叉编译；Linux `GET /healthz` 实际 HTTP 运行通过。
- 本环境没有 Android SDK/AGP 依赖缓存，无法进行完整 Android APK 构建，也未运行红米 K90 / 小米 10 真机测试。

## 预期与未承诺

- 目标：室外尽量采用高质量卫星/融合定位，争取米级；家长端约每 1 秒尝试刷新最新位置。
- 不能承诺：真实定位每秒必定更新、持续 1–3 米精度、室内保证米级、手机断电后继续定位、Android 进程强制结束后无条件自动恢复。
- **未配置高德 Key 时，应用内不存在地图底图；家长端实时看到经纬度，点击后才能在外部地图上查看当时坐标快照。**
