# FamilyGuard V5.3 发布前复审

## 范围
检查 Go 服务端、Android 原生定位与上传、家庭配对权限、电子围栏、SOS 本地队列、媒体请求/文件上传、Nginx/systemd 配置。对能执行的单元与集成测试重新运行。

## 复审修复
1. 首次创建家庭在 `FG_SINGLE_FAMILY=1` 环境缺少初始化认证时存在公网抢注机会：添加至少 32 字符的 `FG_SETUP_TOKEN`，家长首次创建家庭需要相同密钥。服务端在首次启动且未设置密钥时拒绝启动。已有家庭可保留已有令牌/恢复密钥。
2. 延迟上传的 SOS 到通知网关时未在通知正文标识最初发生时间：新增发生时间及延迟送达提示。
3. 紧急通知批处理原为近似无优先级顺序：在同批通知中优先发送 SOS。
4. 新增并发上传位置/发送 SOS 的压力用例，验证同一个家庭写入、读取和访问权限，使用 Go 竞态检测执行。
5. 新增 Ubuntu 部署及备份/故障回滚脚本，不覆盖其他业务 Nginx 配置；首次密钥只在部署终端展示一次。

## 测试证据
- Go 测试、竞态检测和 `go vet`：实际通过（见发布过程记录）。
- 纯 Java 核心策略测试（AccuracyPolicy、CoordinateReference、ServerAddress）：共 53 个断言通过。
- 真实 HTTP loopback 启动：创建家庭前未带正确部署密钥被拒绝，正确密钥创建家庭、配对、设置围栏、发送 SOS、家长读取、越权拒绝、禁止创建第二家庭，通过。
- 代码构建：重新生成 Windows amd64、Linux amd64 Go 服务端二进制。
- Bash 部署脚本已做语法检查；当前环境 Nginx 语法测试通过，但**没有以目标云服务器的现有 Nginx 配置进行完整部署测试**。

## 不能声称已通过的项目
- Android 完整 APK Gradle 构建（当前执行环境缺少 Android SDK/在线 Gradle 依赖）。
- 红米 K90 和小米 10 的移动网络异地、锁屏、重启、位置误差、音视频实际上传与播放。
- 目标云服务器 SSH 登录、真实 TLS/域名/安全组、真实通知送达。
- 远程自动在锁屏后台打开孩子手机摄像头/麦克风：本工程未提供。

## 仍需注意的边界
- Android 和地图 SDK 的运行稳定性只能靠完整构建与两台手机的真机测试证明。
- 电子围栏通过位置上报判断，手机断网时服务器不会立即获知离开；只有恢复网络后才能看到新位置。
- 没有配置外部紧急通知通道时，服务器事件不会自动推送到家长锁屏手机。
- 家长设备上显示的系统水平精度（比如 ±5 米）不是实测偏差或保证精度。
